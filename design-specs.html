🔄 Usage Patterns & Best Practices

Functional Categories

  • User Input: Research, personalization, feedback forms
  • Confirmation: Delete actions, destructive operations
  • Notification: Limits, updates, announcements
  • Selection: Options, settings, preferences
  • Preview: Image display, content viewing

Interaction Patterns

  • ESC Key: Always closes modal (except non-closable)
  • Click Outside: Closes modal on backdrop click
  • Focus Management: Auto-focus first input element
  • Button Order: Cancel left, Primary action right
  • Loading States: Disable interactions during async operations

🏗️ Component Architecture

Standard Modal Structure

<template>
  <n-modal v-model:show="showModal" :mask-closable="true">
    <div class="modal-container">
      <div class="modal-header">
        <h2>{{ $t('modal.title') }}</h2>
        <button @click="closeModal" class="close-btn">×</button>
      </div>
      <div class="modal-body">
        <!-- Modal content -->
      </div>
      <div class="modal-footer">
        <button @click="closeModal" class="btn-cancel">Cancel</button>
        <button @click="confirmAction" class="btn-primary">Confirm</button>
      </div>
    </div>
  </n-modal>
</template>

📋 Development Guidelines

✅ Do

  • Use consistent sizing (361px, 500-600px, 800px+)
  • Implement proper focus management
  • Add ESC key and backdrop click handlers
  • Use i18n for all text content
  • Follow button color standards

❌ Don't

  • Create custom modal overlays without framework
  • Use arbitrary sizes outside the standard system
  • Forget to handle loading and error states
  • Mix different UI frameworks in same modal
  • Hardcode text strings in templates
